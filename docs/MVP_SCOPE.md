# IbuDaya — MVP Scope

> Every feature is classified:
> - **P0** — competition critical. The demo fails or looks incomplete without it.
> - **P0-Lite** — competition critical, but shipped in a deliberately minimal,
>   reliable form (a subset of the full feature).
> - **P1** — valuable. Include if time allows; safe to cut without breaking the story.
> - **P2** — post-MVP. Explicitly deferred.
>
> Honesty labels (decision #10): `IMPLEMENTED`, `DEMO_SIMULATION`,
> `PROTOTYPE_DECISION`, `ASSUMPTION`, `FUTURE_IMPLEMENTATION`. "Canned" =
> `DEMO_SIMULATION`: pre-scripted demo output, no model / OCR / network.

## 3. Non-goals for this MVP

- No network calls of any kind in the demo build (`RemoteRepository` interfaces
  may exist but must not be wired).
- No real camera OCR, computer vision, weather API, or ML inference.
- No real money movement, loan approval, underwriting, disbursement, or
  representation as a regulated lender / financial partner (decision #6).
- **No financing application submission** — no "Ajukan", "Kirim Pengajuan",
  "Pengajuan Terkirim", or approval/status screens (CR-2). Financing ends at the
  simulation result (SC-11).
- **No roof financial projection** in P0 — no savings figure, payback/ROI, or
  capacity calculation on the roof screen (CR-13).
- No blockchain / on-chain ledger, and no UI wording implying it (decision #8).
- No login, signup, KYC, or password entry.
- No AI-accuracy figures, confidence probabilities, or measurement-precision
  claims anywhere in the UI (decision #2).
- No iOS build, no tablet layout, no landscape, no dark mode.
- No server-side anything.

## 4. Definition of Done (MVP)

A feature is done when:

1. It works end-to-end in Demo Mode with airplane mode on.
2. It renders correctly at 360 dp and 412 dp width with no RenderFlex overflow.
3. Loading / empty / error / success states are handled where the screen loads data.
4. All user-facing strings are in the centralised Indonesian string source.
5. Colours and spacing come from design tokens (all labelled `PROTOTYPE_DECISION`),
   not literals.
6. `dart format` applied; `flutter analyze` reports no errors or warnings.
7. `DemoCreditScoringEngine` and `LoanSimulation` logic have passing unit tests,
   including the canonical Ibu Clara score (82) and the three loan tenor rows
   (`DATA_MODEL.md §4.3`).
8. Every `DEMO_SIMULATION` value on screen carries a visible qualifier, and
   financing shows the "bukan penawaran resmi" disclaimer.
9. The screen's acceptance criteria in `SCREEN_INVENTORY.md` are met.
10. The relevant step of `DEMO_SCRIPT.md` can be performed without improvisation.
